# 排版与内容手册（wk-marp-slide）

> 写 `index.md` 之前先读这份手册，再读 `../template/style-sample.md`（一份真实排版的样张）。
> 规则配样例看；骨架从 `../template/index.md` 抄。

## 1. 页面解剖：三层，各司其职

一个 Marp 页面由三层构成，**各管各的，不要互相越权**。

| 层 | 谁控制 | 长什么样 |
|---|---|---|
| **固定层** | front matter | 页眉 `header:`（左上，小号灰字）、页脚 `footer:`（左下）、页码（右下，主题生成的 `section::after`） |
| **页标题** | `##` | 一页**只有一个**，左对齐，字号最大。内容页的"这句话在讲什么" |
| **栏标题** | `###` | 只在 `.col` 里出现，被主题规则 `.col h3{text-align:center}` **自动居中** |
| **正文** | markdown | 22px 基准，行距由主题给定 |

```markdown
---
marp: true
theme: main
headingDivider: 2      # ← # 和 ## 都是分页符，### 不是
paginate: true
header: 幻灯片的排版语汇
footer: wk-marp-slide · 版式样张
math: mathjax          # ← 需要公式时才留
---
```

**`headingDivider: 2` 是全局的地基**：`#` 和 `##` 都会另起一页。副作用是 —— 写在 `<div>` 里的 `#` / `##` **也会分页，把块劈成两半**（见 §9）。

## 2. 版式决策表：内容类型 → 版式 → 骨架

**先查表，再动手写。** 不要凭感觉决定一页长什么样。

| 内容类型 | 版式 | 骨架 |
|---|---|---|
| 两个对等维度 | 双栏 | `.container` + `.col` × 2 |
| 三个对等维度 | 三栏 | `.container` + `.col` × 3（内容多时加 `smallfont`） |
| 主次不均（一条主线 + 若干附属） | 非对称 | `.col2` + `.col`（`.col2` 占两倍宽） |
| 一组对比 + 另一组对比 | 三栏 ×2 + 分隔线 | 两段 `.container`，中间一条 `<hr>` |
| 四张图 + 短注 | 四栏图卡 | `.container` + `.col` × 4，每栏 `![h:250px]` + 2 条注 |
| 一张大图 + 短文 | 图文分屏 | `![bg fit left:30%](...)` + 正文 |
| 字段对照 / 清单 | 宽表 | `.centerblock` 包 `table`，结论写在表下 |
| 流程 / 结构 / 依赖 | 图或 mermaid | `<div class="mermaid">` 或一张 SVG |
| 引文 / 出处 / 参考 | 页角脚注 | `<div class="rightBottomInPage smallestfont">` |
| 章节切换 | 章节页 | `# 标题` + `<!-- _class: chapter -->` |

**选型的三个问题**：

1. 这一页的几块内容，读者会**平着看**还是**上下看**？平着看 → 分栏；上下看 → 分隔线分段。
2. 几块内容**地位相同**吗？不同 → 用 `.col2` / `.col` 做非对称。
3. 有没有**图**？有 → 图占 60%、注占 40%；没有 → 别硬塞图。

## 3. 同页分隔线：`<hr>`

一页要放**两组**信息时，用一条满宽细线把上下分开。

```markdown
<div class="container"><div class="col">
### 上半部分
- …
</div><div class="col">
### 上半部分
- …
</div></div>

<hr>

<div class="container"><div class="col">
- 下半部分
</div><div class="col">
- 下半部分
</div></div>
```

- **`<hr>` 前后各留一个空行**（否则会被当成段内联 HTML 解析，样式跑掉）。
- `<hr>` 是裸 HTML，**不分页**，渲染成整幅干净的细横线。
- 等价写法 `> ---`（blockquote 包住的分隔线）：**同样不分页**，但左端会多一个 ~3px 的小方块（blockquote 的 `border-left` 残留）。
- **顶格 `---` 和 `***` 都会分页**！Marpit 把任何顶格 thematic break 当分页符。别拿来当分隔线。
- 一页最多一条分隔线。再多，说明这一页该拆。

## 4. 栏位系统

### 选择树

```
内容分几块？
├─ 2 块 → .col × 2
├─ 3 块 → .col × 3
├─ 4 块 → .col × 4
└─ 主次不均 → .col2（主）+ .col（次）
```

### 类速查

| 类 | 作用 | 用法 |
|---|---|---|
| `.container` | 横向 flex，分栏的父容器 | `<div class="container">…</div>` |
| `.col` | 等宽一栏 | `<div class="col">…</div>` |
| `.col2` | 两倍宽的一栏 | 和 `.col` 混用做非对称 |
| `.colv` | 纵向居中的一栏 | `align-items` 声明无效（是 `left` 不是 `flex-start`），实际表现与 `.col` 接近 |
| `.centerblock` | 块内整体居中 | 包表格 / 大图 |
| `.onleft` / `.oncenter` / `.onright` | 块内文字对齐 | 和字号类叠用：`<div class="smallfont oncenter">` |
| `.smallfont` / `.smallerfont` / `.smallestfont` | 0.8em / 0.7em / 0.6em | 密集块降一级、脚注降两级 |
| `.rightTopInPage` / `.rightBottomInPage` / `.leftBottomInPage` | 页内绝对定位 | 放脚注、出处、参考 |
| `section.face` | 封面 | `<!-- _class: face -->` |
| `section.chapter` | 章节页（蓝底白字横条） | `<!-- _class: chapter -->` |

### 嵌套的规矩

- `.container` 可以套 `.container`（内层独立分栏）。
- **`<div>` 里绝不能出现 `#` 或 `##`** —— 会分页并把块劈成两半（`###` 可以，主题规则让 `###` 在栏里居中）。
- `<div>` 要成对闭合。检查器会数 `<div` 与 `</div>` 的数量。

## 5. 图文混排

### 图卡（多图并排）

```markdown
<div class="container"><div class="col">
![h:250px](img/a.png)
- **标题**
- 一行短注
</div><div class="col">
![h:250px](img/b.png)
- …
</div></div>
```

- **必须定尺**：`![h:250px]`（按高）或 `![w:300px]`（按宽）。不定尺的图会撑破栏宽。
- 所有图**同一个 `h:` 值**，视觉才对齐。
- 图下 **1 条标题 + 1–2 条短注**。不要写整段说明。
- 图占约六成高度，注占四成。

### 分屏（大图压一侧）

```markdown
![bg fit left:30%](img/poster.png)

- **正文**：一条硬信息 + 一条判断
- 第二条
- 第三条
```

- `![bg fit left:30%]` —— 图占左侧 30%，正文自动排到右侧 70%。
- **`fit` 是 contain**：图的宽高比和分区不一致时，图不会铺满，会露白。想铺满就按分区比例做图（30% 分区 = 宽高比 0.533，如 800×1500），或去掉 `fit` 改用 `cover`。
- 分屏页正文 **≤ 8 条**。超了就换页。
- 分屏页**不要放表格** —— 表格需要整块宽度。

## 6. 表格与脚注

```markdown
<div class="centerblock">

| 版式 | 何时用 | 骨架 |
| --- | --- | --- |
| 双栏 | 两个对等维度 | `.container` + `.col` × 2 |
| 三栏 | 三个对等维度 | `.container` + `.col` × 3 |

</div>

- **结论写在表下面**，不要塞进表里
- 一页最多一张表

<div class="rightBottomInPage smallestfont">
出处：XXX, 2026
</div>
```

- **表只放"对照关系"**（字段 × 取值），判断和结论写在表下面的 bullet 里。
- 首列加粗。
- 宽表用 `.centerblock` 居中（`display:flex` 会让表格按内容收缩，不用它表格会偏左）。
- 脚注 / 出处 / 参考落**右下角**（`.rightBottomInPage smallestfont`），不要和正文混在一起。

## 7. 密度：一页能装多少

### 定义

**加权密度 = 内容行数 + 3 × 图片行数**

一行图约等于三行正文（它占的垂直空间更大）。

### 基线（来自一份 74 页的真实 deck 实测）

| 指标 | 数值 |
|---|---|
| 正文页加权密度 **中位** | **17** |
| 正文页加权密度 **均值** | **20** |
| 典型区间 | **8 – 32** |
| 低于 8 的页占比 | 12% |
| 单栏 bullet 数 | 4 – 6 条 |
| 单条 bullet 长度 | ≤ 60 字 |

### 阈值

| 情况 | 判断 | 动作 |
|---|---|---|
| 加权密度 < 8 | 页面发空 | 与相邻页**合并**（首选），不是加图 |
| 连续 2 页 < 6 | 明显发空 | 合并；合并前先确认两页是不是同一个论点 |
| 加权密度 > 32 | 有溢出风险 | 拆页或换版式 |
| 单栏 > 6 条 bullet | 太挤 | 分栏，或用 `<hr>` 分段 |
| 单条 > 60 字 | 太长 | 拆成两条，或压成短句 |

**溢出是静默的** —— 内容被裁掉，页面看起来还正常。所以必须**渲染出来看**（见 §11）。

**章节页、封面、尾页不参与密度统计** —— 它们天然只有一行。

## 8. 内容深度：怎么写才不"初级"

判据很简单：**一条 bullet 要是一个完整短句，不是一个名词短语。**

### 成对示例

| ❌ 不合格 | ✅ 合格 |
|---|---|
| `- 标准、规范` | `- **ISO/IEC 30173:2023** 规定了数字孪生的三层参考架构` |
| `- 支持多种格式` | `- 支持 **21** 项 SISO 标准，覆盖制造过程数据交换` |
| `- 性能优化` | `- 采样率提升到 **48 kHz**，端到端延迟降到 **120 ms`** |
| `- 与其它工具兼容` | `- 与 **LangChain / LlamaIndex** 共用同一套 Tool 接口` |
| `- A 不同于 B` | `- **A 是离线建模**，**B 是实时同步** —— 差在数据更新频率` |
| `- 支持导出` | `- 导出 **PDF / PNG / HTML** 三种格式，PDF 走 Chrome 无头渲染` |

### 六条规则

1. **完整短句。** 有主语、有判断，不是名词罗列。
2. **每页至少 1 条硬信息** —— 数字、版本号、年份、机构名、具体判定，至少一个。
3. **先给判断，再给依据。** 结论前置，理由跟在后面。
4. **对比写成对照句**，不写"A 与 B 不同"。
5. **一页一个论点。** 第二个论点用 `<hr>` 分段，不是再堆 bullet。
6. **术语首次出现给一句话定义**，之后直接用。

### 自查

出现「支持 / 多种 / 若干 / 等等 / 相关 / 比较 / 优化」这类**空词**，而同行又没有具体的名词或数字 → **判为不合格，重写**。

## 9. 叙事结构（deck 级）

```
封面 → 目录 → 章节页 → 内容页 ×(3-8) → 章节页 → … → 小结页 → 尾页
```

- **章节页**（`# 标题` + `<!-- _class: chapter -->` → 蓝底白字横条）每 **5–8 页**出现一次，作为节奏锚点。它不承载信息，只承载"我们讲到哪了"。
- **目录页要真链接**：`- [章节名](#章节名)`。锚点是标题文字（中文按 URL 编码，Marp 会自动匹配，直接写中文即可）。
- **收尾要有小结页**，不要从内容页直接跳到尾页。小结页把方法压成可执行清单。
- 一级标题用 `#`，二级用 `##` —— 目录页只列一级。

## 10. 反模式速查

| 反模式 | ❌ | ✅ |
|---|---|---|
| 一页一个 bullet | `## 标题`<br>`- 只有一条` | 一页讲一个论点，但用 2–4 栏或表格把它拆开 |
| 整页文字墙 | 连续 12 行 bullet | `.container` 分栏 + `smallfont` |
| 图随手贴 | `![](big.png)` | `![h:250px](big.png)` + 短注 |
| 分隔线用错 | 顶格 `---` | `<hr>`（同页分段）/ 顶格 `---`（分页） |
| `--` 紧跟标题 | `---` 然后 `## 标题` | 删掉 `---`（会多出一张空页） |
| `<div>` 里写标题 | `<div>` 内 `## 标题` | 换成 `<h2>`，或把标题移出 div |
| 章节页缺 class | `# 标题`（普通大字） | `# 标题` + `<!-- _class: chapter -->` |
| 全是占位符 | `- 条目一` | 完整短句 + 硬信息 |
| 脚注混进正文 | 末尾一条 `- 参考：…` | `<div class="rightBottomInPage smallestfont">` |

## 11. 实测机制与坑

### Marp 分页语义（全部实测过）

| 写法 | 行为 |
|---|---|
| 顶格 `---` | **分页**。新页没有 `##` 标题（是"续页"），全局 header/footer/paginate 延续 |
| 顶格 `---` 紧跟标题 | **多出一张空页**（`---` 开一页、标题再开一页） |
| 顶格 `***` / `___` | **分页**（Marpit 把任何顶格 thematic break 当分页符） |
| `> ---` | **不分页**，渲染成满宽细线（左端有个 3px 小方块） |
| `<hr>` | **不分页**，渲染成满宽干净细线 |
| `---` 写在 HTML 注释块内 | **不分页**（注释块被跳过） |
| `<div>` 内的 `#` / `##` | **分页**，并把 div 劈成两半 |
| `<div>` 内的 `###` | 不分页（`headingDivider: 2` 只切 h1/h2） |

### 构建坑

1. **PDF/PNG 必须加 `--html`。** Marp 默认把 raw HTML 转义成文本 —— Mermaid 图变成源码、`<div class="container">` 分栏塌成一坨、Heti 完全失效。`build.sh` 已默认带上。
2. **单文件模式 `--images png` 不带扩展名** —— 产物是 `index.001` 而不是 `index.001.png`。`build.sh` 构建后统一改名。
3. **`-o <dir>` 只在 `-I <dir>`（输入目录）模式下可用**；给多个文件传 `-o <dir>` 会报 *"Output path cannot specify with processing multiple files"*。
4. **`mermaid.min.js` 必须与 md 同目录**，且用 `./mermaid.min.js` 相对路径引用。
5. **PNG/PDF 里的相对图片路径按 md 所在目录解析**；HTML 里的相对路径按**输出 html 所在目录**解析 —— 所以脚本在 `dist/html/` 里软链了 `images/`、`img/`、`mermaid.min.js`。
6. **章节锚点**：中文标题的 id 是 URL 编码的。Marp 会自动把正文里的中文锚点链接编码成匹配的形式，直接写 `#一级目录` 即可。
7. **临时母版文件**：`build.sh -b <brand>` 会在 deck 目录生成 `build-<brand>.md`，构建结束自动删除。**不要**提交进 git。
8. **Mermaid 图**：在文件**末尾**（最后一个 `---` 之后）加
   ```markdown
   <!-- mermaid.js -->
   <script src="./mermaid.min.js"></script>
   <script>mermaid.initialize({startOnLoad:true});</script>
   ```
   少了这段，图不会渲染成 SVG，而是显示源码。

### 中文古典排版（Heti）

`main.css` 内置了 Heti（[sivan/heti](https://github.com/sivan/heti)），用于古诗文、竖排等场景。

**用显式 HTML 标签写标题**（`<h1>` / `<p>`），不要用 Markdown 的 `#`：

```markdown
<div class="heti heti--ancient">
<h1>出师表</h1>
<p>先帝创业未半而中道崩殂，今天下三分。</p>
</div>
```

原因：`headingDivider: 2` 让 `#` / `##` 成为**分页符**，写在 `<div>` 里会把块从中间劈成两页。`<h1>` 是普通 HTML，不触发分页。

可用变体：`heti--ancient`（古文）、`heti--poetry`（诗词）、`heti--columns-2`（分栏）、`heti--vertical`（竖排）、`heti--annotation`（夹注）、`heti--song` / `heti--hei` / `heti--kai`（字体）。

## 12. 交付前自检

1. `scripts/check_layout.py <deck_dir>` —— 静态检查，0 ERROR 才算过。
   **不依赖视觉能力，两种模型都要跑。**
2. 构建 PNG，**自己 Read 逐页长图**看一遍 —— **仅当你有视觉能力时做**：
   - 有没有**空白页**？
   - 有没有**溢出**（底部被裁、字压到页脚）？
   - 有没有**塌陷**（分栏挤成一条、图撑破栏）？
   - 有没有**连续 2 页太空**（加权密度 < 6）？
   - 有没有**孤儿标题**（只有标题没内容）？
   - 分隔线是不是**满宽细线**，而不是被当成新的一页？
3. 改完**重新构建再看一遍**。修完再交付给用户。

**没有视觉能力的模型**：跳过第 2、3 步，只做静态检查；交付时如实说明
"我没有视觉能力，无法自查渲染效果"，并把 PNG / PDF 的路径给用户去核对。
**不要假装看过。**
